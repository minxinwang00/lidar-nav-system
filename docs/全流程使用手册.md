# LiDAR 导航系统全流程使用手册

> 适用工作空间：`~/nav_system_ws`  
> 适用环境：Ubuntu 22.04 + ROS 2 Humble  
> 更新日期：2026-10-31

> **重要提示**：当前工作空间中的 `occupancy_map.*` 曾被仿真测试地图覆盖。
> 实车导航前请先重新建图，或从备份恢复真实地图，确认地图与实际场地一致后再导航。

---

## 1. 系统概览

本系统由四层组成：

```text
第 1 层  传感器驱动
         Livox MID-360 -> /livox/lidar、/livox/imu

第 2 层  建图与定位
         FAST-LIO -> /Odometry、/cloud_registered
         grid_mapping -> /local_costmap、/grid_map/global
         AMCL -> map -> odom

第 3 层  决策与控制
         decision_core（行为树 + A* + DWA）-> /plan、/cmd_vel、/nav_status

第 4 层  用户交互
         nav_gui（Qt 控制台）、RViz、底盘串口桥
```

核心数据流：

```text
/livox/lidar + /livox/imu
        │
        ▼
    FAST-LIO
        │  /Odometry、/cloud_registered
        ├──────────────► grid_mapping ──► /local_costmap
        │                                   │
        ├──────────────► cloud_to_scan ──► /scan ──► AMCL ──► map→odom
        │                                                       │
        └──────────────────────────────► decision_core ◄────────┘
                                             │
                                             ├──► /plan
                                             ├──► /cmd_vel ──► chassis_bridge ──► 底盘
                                             └──► /nav_status ──► GUI
```

TF 树：

```text
map --(AMCL 动态)--> odom --(FAST-LIO 50Hz)--> base_link
                         │
                         └──► camera_init --(FAST-LIO)--> body --(static)--> livox_frame
```

主要包：

| 包 | 作用 |
|---|---|
| `livox_ros_driver2` | MID-360 驱动 |
| `fast_lio` | LiDAR-IMU 里程计与 3D 点云 |
| `grid_mapping` | 3D 点云转 2D 栅格/局部代价地图 |
| `nav_localization` | LIO/AMCL TF 桥、点云转 `/scan` |
| `decision_core` | 行为树、全局 A*、DWA、局部绕行、恢复行为 |
| `chassis` | `/cmd_vel` -> MiniPC 二进制底盘帧 |
| `nav_gui` | Qt 操作控制台 |
| `bringup` | 建图/导航统一启动文件 |
| `nav_sim` | 无硬件仿真 |
| `li_init_tools` | LI-Init 标定数据录制与结果应用 |

## 3. 外参估计

### 3.0 当前默认：FAST-LIO 在线外参估计

当前工作空间已放弃 LI-Init 流程，默认配置：

```text
src/mapping/FAST_LIO/config/mid360.yaml
```

关键参数：

```yaml
mapping:
  extrinsic_est_en: true
  extrinsic_T: [0.0, 0.0, 0.0]
  extrinsic_R: [1., 0., 0.,
                0., 1., 0.,
                0., 0., 1.]
```

说明：

- FAST-LIO 会在运行过程中在线估计 LiDAR 与 IMU 的旋转 `R` 和平移 `T`；
- 单位旋转/零平移作为初值；MID-360 的 LiDAR 与 IMU 内部安装外参较小，通常可收敛；
- 在线估计不估计 LiDAR 与 IMU 的**时间偏移**，时间同步仍按硬件时间戳；
- 开始运动后前 10~30 秒为收敛阶段，建图时先低速、避免剧烈旋转；
- 如果已知厂家外参，填入 `extrinsic_T/R` 作为初值可加快收敛。

启动建图前，如果终端加载了 MVS 相机 SDK，可能出现：

```text
symbol lookup error: libpcl_io.so.1.12: undefined symbol: libusb_set_option
```

原因是 `/opt/MVS/lib/64` 里的旧 `libusb` 覆盖了系统库。

`mapping.launch.py` / `navigation.launch.py` 已经只对 FAST-LIO 进程预加载系统
`libusb-1.0.so.0`，正常启动不需要手动处理。

如果是手动 `ros2 run fast_lio fastlio_mapping`，需要先执行：

```bash
export LD_LIBRARY_PATH=/lib/x86_64-linux-gnu:$LD_LIBRARY_PATH
```

验证参数：

```bash
ros2 param get /laser_mapping mapping.extrinsic_est_en
# True
```

### 3.0.1 MID-360 倾斜安装（前置 10 cm、上倾 45°）

在线外参估计只处理 LiDAR ↔ IMU 的相对外参，**不能**估计传感器相对车体/重力的
45° 安装角。当前代码已做两处处理：

1. FAST-LIO 初始化时把初始世界坐标系与重力对齐：
   - 文件：`src/mapping/FAST_LIO/src/IMU_Processing.hpp`
   - 使用静止加速度把世界 z 轴对齐到重力反方向；
   - 这样即使雷达斜装，`camera_init` 的 z 轴也是竖直的，2D 栅格的
     `z_min/z_max` 才有意义。

2. `base_link` 补偿传感器前置 10 cm：
   - `mapping.launch.py` / `navigation.launch.py`
   - `base_to_body_x: -0.10`
   - 如果实际前置距离不是 10 cm，或方向相反，修改这个值。

验证：

```bash
ros2 topic echo /Odometry --once
ros2 run tf2_ros tf2_echo map camera_init
ros2 run tf2_ros tf2_echo map base_link
```

静止时：

- `camera_init` 应基本水平；
- `/Odometry` 的 roll 接近 0，pitch 约等于实际安装俯仰角（约 45°）；
- RViz 中地面应水平，而不是倾斜。

如果 pitch 接近 0，说明重力对齐没有生效；如果出现 90°/135° 等异常值，
检查加速度符号或安装方向。

### 3.1 可选：LI-Init 离线标定

> 当前默认不使用 LI-Init；以下流程保留给需要离线高精度标定的场景。

LI-Init 用于估计 LiDAR 到 IMU 的旋转、平移和时间偏移。

#### 3.1.1 启动标定数据录制

```bash
cd ~/nav_system_ws
source /opt/ros/humble/setup.bash
source install/setup.bash

ros2 launch li_init_tools calibrate.launch.py \
  use_chassis:=true \
  bag_duration:=90
```

如果底盘由遥控器控制，使用 `use_chassis:=false`。

开始录制：

```bash
ros2 service call /li_init_manager/record_bag std_srvs/srv/Trigger {}
```

录制期间需要充分激励：

- 绕 X/Y/Z 三个轴旋转；
- 前后左右移动；
- 不要长时间静止；
- 建议 60~120 秒；
- 确认 `/livox/lidar` 和 `/livox/imu` 持续有数据。

提前结束录制：

```bash
ros2 service call /li_init_manager/stop_recording std_srvs/srv/Trigger {}
```

bag 保存到：

```text
~/nav_system_ws/calib_bags/li_init_YYYYmmdd_HHMMSS
```

查看状态：

```bash
ros2 topic echo /li_init_status
```

### 3.2 运行 LI-Init

原版 LI-Init 是 ROS1 工程，当前工作空间不包含它的算法源码。联网后可以尝试：

```bash
bash src/calibration/li_init_tools/scripts/install_li_init.sh
```

若上游是 ROS1 包，需要在 ROS1 Noetic 容器/工作区中运行，或使用 ROS2 移植版本。
运行 LI-Init 后，把结果保存为：

```text
~/nav_system_ws/calib_bags/li_init_result.txt
```

支持的文本格式示例：

```text
Rotation LiDAR to IMU:
 0.9999  0.0010 -0.0020
-0.0010  0.9999  0.0005
 0.0020 -0.0005  0.9999
Translation LiDAR to IMU:
 0.012 -0.003 0.045
Time offset: -0.0021
```

### 3.3 应用标定结果

```bash
ros2 service call /li_init_manager/apply_result std_srvs/srv/Trigger {}
```

生成：

```text
src/mapping/FAST_LIO/config/mid360_calibrated.yaml
```

也可以直接命令行生成：

```bash
ros2 run li_init_tools apply_li_init \
  --result ~/nav_system_ws/calib_bags/li_init_result.txt \
  --input src/mapping/FAST_LIO/config/mid360.yaml \
  --output src/mapping/FAST_LIO/config/mid360_calibrated.yaml
```

### 3.4 使用标定配置

建图：

```bash
ros2 launch bringup mapping.launch.py \
  lio_config:=$HOME/nav_system_ws/src/mapping/FAST_LIO/config/mid360_calibrated.yaml
```

导航：

```bash
ros2 launch bringup navigation.launch.py \
  map_yaml:=$HOME/nav_system_ws/src/mapping/maps/occupancy_map.yaml \
  lio_config:=$HOME/nav_system_ws/src/mapping/FAST_LIO/config/mid360_calibrated.yaml \
  use_gui:=true \
```

### 3.5 在线估计的验证与注意事项

启动 FAST-LIO 后检查：

```bash
ros2 param get /laser_mapping mapping.extrinsic_est_en
ros2 topic hz /Odometry
ros2 topic hz /cloud_registered
```

建议：

1. 静止 10~20 秒，让 IMU 初始化和重力对齐完成；
2. 先低速直行和缓慢转向，给外参估计收敛时间；
3. 观察建图是否出现明显重影、墙面弯曲、z 方向漂移；
4. 若外参收敛差，先填入已知厂家外参作为初值，再降低运动速度；
5. 在线估计不补偿时间偏移；时间同步异常时需要单独处理时间戳。

如果在线估计仍不能满足精度要求，再考虑可选的 LI-Init 离线标定流程。


- `lio_odom_bridge`；
- `grid_mapping`；

```bash

  use_rviz:=false
```

### 4.2 检查传感器

新开终端：

```bash
source /opt/ros/humble/setup.bash
source ~/nav_system_ws/install/setup.bash

ros2 topic hz /livox/lidar
ros2 topic hz /livox/imu
ros2 topic hz /cloud_registered
ros2 topic hz /Odometry
ros2 topic hz /local_costmap
```

期望：

- `/livox/lidar` 约 10 Hz；
- `/livox/imu` 约 200 Hz（以实际驱动配置为准）；
- `/cloud_registered`、`/Odometry` 连续；
- `/local_costmap` 约 10 Hz。

RViz 中确认：

- Fixed Frame 为 `map`；
- 点云随机器人移动；
- TF `map -> odom -> base_link` 连续；
- `/local_costmap` 中能看到障碍物。

### 4.2.1 Qt 界面中的 TF / 节点诊断

左侧“TF 树 / 节点拉起状态”面板每秒刷新：

- `map <- odom`：AMCL 或静态桥；
- `odom <- base_link`：LIO 里程计桥；
- `odom <- camera_init`、`camera_init <- body`、`body <- livox_frame`；
- `map <- base_link`：组合位姿。

每行显示 `OK/FAIL`、时间戳年龄、平移和 yaw；节点列表显示
`OK/MISSING`，可直接看出哪个节点没拉起。

RViz 中新增：

- `Local Costmap`：`/local_costmap`，Volatile/Reliable，costmap 配色；
  **这是膨胀后的代价地图**，紫色/渐变色表示膨胀代价。
- `Local Obstacles (raw)`：`/local_obstacles_raw`，膨胀前的原始障碍栅格；
  用来区分“真实障碍点”和“膨胀出来的紫色区域”。
- `Global Grid`：`/grid_map/global`，Transient Local。

如果 RViz 里看不到代价地图：

1. 必须用新的 `nav.rviz` 重新启动 RViz，旧 RViz 不会自动加载新增显示；
2. 确认 Fixed Frame 是 `map`；
3. 确认 GUI 面板里 `pointcloud_to_grid` 是 `OK`；
4. 检查话题：

```bash
ros2 topic hz /local_costmap
ros2 topic echo /local_obstacles_raw --once
```

如果 `Local Obstacles (raw)` 前方也有跳动的点，说明是点云里的真实回波
（可能是车身/安装件/天花板/地面），不是膨胀算法凭空产生的。此时优先调：

```text
src/mapping/grid_mapping/config/grid_params.yaml
min_range
z_min
z_max
```

当前 `min_range` 已从 0.15 提高到 0.35，用于过滤车体近处回波。
`inflate_unknown` 默认改为 `false`：只膨胀已知空闲格，未知区域保持 -1，
避免未观测区域被膨胀成大片紫色假障碍。若动态避障需要更强保守性，可改回 `true`。

注意：

- `z_min/z_max` 只作用于全局累积地图 `/grid_map/global`；
- 局部代价地图 `/local_costmap` 和 `/local_obstacles_raw` 使用
  `local_z_min/local_z_max`，只改 `z_min` 不会影响它们；
- 修改 `src/.../grid_params.yaml` 后必须重新编译，否则 launch 读取的是
  `install/` 里的旧配置：
  `colcon build --packages-select grid_mapping`；
- 已累积的全局地图不会因为改参数自动清除，需要重新“开始建图”或重启建图节点。

### 4.2.1 未知空洞填充

稀疏点云会让空地中间留下没有点云命中的未知格。规划器
`allow_unknown: false` 会把这些未知格当成障碍，导致路径绕开空地中央。

`grid_params.yaml` 新增：

```yaml
fill_enclosed_unknown: true
```

规则：

- 接触栅格边界的未知区域保留，避免把传感器视野外当成空地；
- 邻接障碍物的未知区域保留，避免把墙后/柱后的盲区填平；
- 被空闲格完全包围、且不接触障碍物的未知块，填成空地。

同一套逻辑同时作用于 `/local_costmap`、`/local_obstacles_raw` 和保存的
全局地图。若现场需要严格保留所有未知区域，可设为 `false`。

### 4.2.2 离散障碍去噪

`grid_params.yaml` 新增：

```yaml
despeckle_obstacles: true
obstacle_min_neighbors: 1      # 8邻域内至少几个障碍邻居
obstacle_min_cluster_cells: 3  # 小于该格数的连通障碍簇整簇删除
```

用于清除彼此之间隔着空白格的孤立障碍点和小障碍团：

- 单个孤立格直接删除；
- 小于 `obstacle_min_cluster_cells` 的连通障碍簇删除；
- 连续墙线、2x2 以上的成片障碍保留。

如果现场有很细的杆状障碍被误删，可把 `obstacle_min_cluster_cells` 调低，
或把 `despeckle_obstacles` 设为 `false`。

### 4.3 开始建图

在 Qt 控制台中：

1. 点击“开始建图”（会清空当前累积地图）；
2. 用遥控器或手动方式让机器人低速行驶；
3. 走完整个区域，尽量形成闭环；
4. 避免快速旋转、剧烈晃动和长时间静止；
5. 观察右侧地图和 RViz 中的点云/栅格。

> 建图启动时 `grid_mapping` 默认已经在累积地图。点击“开始建图”的作用是清空旧数据、
> 开始一次全新的建图。

### 4.4 结束建图并保存

点击“结束建图并自动保存”。

保存文件：

```text
src/mapping/maps/occupancy_map_YYYYmmdd_HHMMSS.pgm
src/mapping/maps/occupancy_map_YYYYmmdd_HHMMSS.yaml
```

同时，建图过程中每 30 秒会自动保存一份：

```text
src/mapping/maps/occupancy_map.pgm
src/mapping/maps/occupancy_map.yaml
```

注意：自动保存会覆盖 `occupancy_map.*`；结束建图生成的带时间戳文件用于保留历史版本。

只保存、不结束建图：

```bash
ros2 service call /pointcloud_to_grid/save_map std_srvs/srv/Trigger {}
```

直接结束建图：

```bash
ros2 service call /pointcloud_to_grid/stop_mapping std_srvs/srv/Trigger {}
```

### 4.5 检查地图

```bash
ls -lt ~/nav_system_ws/src/mapping/maps/*.yaml
cat ~/nav_system_ws/src/mapping/maps/occupancy_map.yaml
```

检查要点：

- `image` 指向的 `.pgm` 存在；
- `resolution` 通常为 `0.05`；
- `origin` 合理；
- 地图中没有大面积异常空洞；
- 墙体连续、闭环处没有明显重影。

### 4.6 关闭建图系统

推荐点击右上角“关闭系统”，二次确认后会停止 launch。

也可以：

```bash
# 在 launch 所在终端按 Ctrl+C
```

检查残留：

```bash
ros2 node list

```

## 5. 地图管理

默认地图目录：

```text
~/nav_system_ws/src/mapping/maps/
```

### 5.1 默认加载最新地图

`navigation.launch.py` 的 `map_yaml` 留空时，会自动选择地图目录下修改时间最新的
`*.yaml`。

```bash
ros2 launch bringup navigation.launch.py use_gui:=true
```

### 5.2 指定地图

```bash
ros2 launch bringup navigation.launch.py \
  map_yaml:=$HOME/nav_system_ws/src/mapping/maps/occupancy_map_20261031_141455.yaml \
  use_gui:=true \
  use_chassis:=true
```

### 5.3 在界面中导入地图

1. 点击“刷新”更新地图列表；
2. 下拉框默认选中最新地图；
3. 点击“导入地图...”选择其它 `.yaml`；
4. 点击“加载到导航”；
5. 加载成功后会在全局重定位开关开启时触发 AMCL 全局重定位；
6. 重新设置初始位姿。

命令行加载地图：

```bash
ros2 service call /map_server/load_map nav2_msgs/srv/LoadMap \
  "{map_url: '/home/mxw/nav_system_ws/src/mapping/maps/occupancy_map.yaml'}"
```

> 当前 Humble 环境下 `nav2_map_server` 对 `file://` 前缀兼容性不好，
> 请直接使用绝对路径。

### 5.4 导入地图失败时

确认：

```bash
ros2 lifecycle get /map_server
ros2 service list | grep load_map
```

`/map_server` 必须是 `active`，并且启动导航时 `map_yaml` 不能为空。


## 7. 底盘配置与调试

> **实车必须先满足：遥控器开机，并切到 NAV / 自动 / 电脑控制模式。**
> 否则 `/cmd_vel` 和串口帧都正常，但底盘完全不执行。
> 2026-11-01 实测：给 NAV 模式遥控器开机后，同样的 `0.2 m/s` 帧立刻生效。

底盘协议为 MiniPC 二进制导航帧，共 20 字节：

```text
偏移  长度  字段
0     1     SOF        0x55
1     1     ID         0x04
2     4     x_speed    float32
6     4     y_speed    float32
10    4     yaw_speed  float32
14    4     w_speed    float32
18    1     scan_mode  bool
19    1     EOF        0xFF
```

映射：

```text
linear.x  -> x_speed
linear.y  -> y_speed
angular.z -> yaw_speed（本车实测有效） / w_speed / both
```

启动参数：

```bash
ros2 launch bringup navigation.launch.py \
  use_gui:=true \
  use_chassis:=true \
  chassis_port:=/dev/ttyACM0 \
  chassis_protocol:=binary \
  chassis_angular_target:=yaw_speed
```

本车实测结论：

- `w_speed` 不能旋转；
- `yaw_speed` 能旋转；
- 正命令产生负偏航，所以 `src/navigation/chassis/config/chassis.yaml` 里
  `invert_angular: true`；
- `x_speed` 正方向与车体前向相反，所以 `invert_linear: true`；
- MID-360 的 `body` x 轴与车体前向相差 180°，所以
  `base_to_body_yaw: 3.141592653589793`；
- 如果换车/换固件，重新执行 `chassis_rotation_sweep` 和
  `chassis_motion_test` 确认。

如果 `chassis_motion_test` 报：

```text
heading_error=+20.0°
```

说明实际运动方向与 `base_link` 朝向有安装 yaw 偏差。用 launch 参数补偿：

```bash
ros2 launch bringup navigation.launch.py \
  use_chassis:=true \
  base_to_body_yaw:=0.35 \
  use_gui:=true
```

单位是弧度。先用 motion_test 测量，再按偏差符号调整；不要直接猜。

检查：

```bash
ros2 topic echo /chassis_status
ros2 topic echo /wheel_odom --once
ros2 topic hz /cmd_vel
```

首次实车测试请把车轮架空，确认方向、速度和急停都正确后再落地。

## 11. 常见问题排查

### 11.1 界面显示“等待 /map”

- `map_yaml` 路径不存在；
- `map_server` 未启动或不是 `active`；
- 地图 yaml 的 `image` 路径错误；
- 没有地图，需要先建图。

检查：

```bash
ros2 lifecycle get /map_server
ros2 service list | grep load_map
cat ~/nav_system_ws/src/mapping/maps/occupancy_map.yaml
```

### 11.2 没有 `/cmd_vel`

- 没有设置初始位姿，AMCL 没有 `map -> odom`；
- 行为树卡在 `MapReady` 或 `GoalAvailable`；
- `/estop` 为 `true`；
- 规划失败。

检查：

```bash
ros2 topic echo /nav_status
ros2 topic echo /estop --once
ros2 topic echo /plan --once
```

### 11.3 有 `/cmd_vel` 但底盘不动

- `use_chassis` 没有设为 `true`；
- `/dev/ttyACM0` 不存在或权限不足；
- `pyserial` 未安装；
- 协议字段不对，尝试 `yaw_speed` 或 `both`；
- 方向反了，修改 `invert_*`；
- 底盘处于急停或未使能。

### 11.4 AMCL 定位漂移 / 不收敛

- 初始位姿错误；
- `/scan` 没有数据；
- 地图与实际环境差异太大；
- 雷达被遮挡或环境特征不足；
- 机器人移动太快。

处理：

1. 重新设置初始位姿；
2. 点击“全局重定位”；
3. 让机器人缓慢移动；
4. 检查 `/scan`；
5. 必要时重新建图。

### 11.5 动态障碍不避让

- `/local_costmap` 没有更新；
- 障碍物不在 `z_min~z_max` 高度范围内；
- 局部代价阈值过高；
- 机器人被卡在狭窄通道。

检查：

```bash
ros2 topic hz /local_costmap
ros2 topic echo /nav_status
```

### 11.6 地图加载失败

- `/map_server/load_map` 不可用：启动导航时没有地图；
- 使用了 `file://` 前缀：改成绝对路径；
- yaml 中 `image` 字段路径错误；
- pgm 文件损坏。

### 11.7 界面地图不显示

- 地图目录没有 yaml；
- yaml 中 `image` 指向的 pgm 不存在；
- 地图文件权限不足；
- Qt 无法读取该图片格式（当前支持 PGM/PNG/BMP 等）。

### 11.8 关闭系统后节点仍在

```bash
pkill -INT -f 'bringup.*navigation.launch.py'
pkill -INT -f 'bringup.*mapping.launch.py'
pkill -INT -f 'nav_sim.*sim_navigation.launch.py'
```

必要时再检查：

```bash
ros2 node list
```

### 11.9 RViz 打不开

```bash
rviz2 -d $(ros2 pkg prefix bringup)/share/bringup/rviz/nav.rviz
```

确认 `DISPLAY` 已设置，Fixed Frame 为 `map`。

### 11.10 机器人卡在墙角转弯处

先判断是“定位问题”“路径贴墙”“控制器转不过去”还是“恢复动作无效”。

**第一步：记录现场**

```bash
ros2 bag record -o corner_debug \
  /map /local_costmap /plan /cmd_vel /nav_status \
  /scan /amcl_pose /Odometry /tf /tf_static
```

在 RViz 中同时显示：

- `/map`
- `/local_costmap`
- `/plan`
- `/scan`
- `/amcl_pose`
- TF

**第二步：看 `/nav_status` 的调试字段**

```bash
ros2 topic echo /nav_status
```

重点字段：

| 字段 | 含义 |
|---|---|
| `blocked` | 控制器认为路径被阻挡 |
| `local_blocked` | 局部窗口检测到障碍 |
| `local_candidates` | 障碍后方可用候选点数量 |
| `local_attempts` | 局部 A* 尝试次数 |
| `local_plan_ok` | 局部 A* 是否成功 |
| `active_local_path` | 当前是否在使用局部绕行路径 |
| `local_path_points` | 局部路径点数 |

如果 `local_blocked=true` 但 `local_attempts=0`，说明局部绕行没有触发；
如果 `local_plan_ok=false`，说明局部 A* 在窗口内找不到可行路径。

**第三步：检查实际车体尺寸**

`robot_radius` 必须填车体的**外接圆半径**，不是半宽：

```text
robot_radius = sqrt((length/2)^2 + (width/2)^2) + 安全余量
```

例如车体 0.60 m × 0.50 m：

```text
robot_radius = sqrt(0.30^2 + 0.25^2) + 0.03 ≈ 0.42 m
```

全局膨胀和局部膨胀都要大于该值：

```yaml
# nav_params.yaml
robot_radius: 0.42
inflation_radius: 0.55
clearance_weight: 2.5

# grid_params.yaml
inflation_radius: 0.55
```

局部代价地图的阻挡范围由阈值决定：

```text
cost = 100 * (1 - distance / inflation_radius)
```

`collision_cost` / `local_blocked_cost` 越大，实际被判定为障碍的范围越小。
要更保守，应**降低**阈值，而不是提高：

```yaml
collision_cost: 20.0
unknown_cost: 10.0
local_blocked_cost: 20.0
```

例如局部膨胀 `0.55 m`、阈值 `20` 时，大约把距障碍 `0.44 m` 以内的格子都视为阻挡，
更接近 `robot_radius=0.42` 的车体尺寸。

**第四步：检查是否“切内角”**

常见原因是 `lookahead` 太大，机器人提前转向切入墙角：

```yaml
lookahead_dist: 0.40   # 可从 0.6 逐步降到 0.4~0.5
max_linear: 0.25       # 拐角先降速
max_dv: 0.10
max_dw: 0.8
```

如果转弯时线速度仍然很高，可以进一步降低 `max_linear`，或在
`controller_plugin.py` 中给 DWA 增加“航向误差越大、允许线速度越小”的约束。

**第五步：检查恢复动作**

```yaml
blocked_timeout: 1.2
recovery_backup_distance: 0.50
recovery_backup_speed: 0.10
recovery_spin_duration: 1.8
recovery_spin_speed: 0.5
```

如果后方空间不足，倒车会被 `BackUp` 拒绝；如果原地旋转会扫到墙，
需要检查 `robot_radius` 和局部膨胀是否偏小。

**第六步：区分仿真问题和实车问题**

用同一张地图在仿真中复现：

```bash
ros2 launch nav_sim sim_navigation.launch.py \
  map_yaml:=$HOME/nav_system_ws/src/mapping/maps/你的地图.yaml
```

- 仿真也卡：优先查路径、膨胀、DWA、局部 A*；
- 只有实车卡：优先查车体尺寸、轮距、旋转中心、底盘方向、AMCL 漂移、
  串口延迟和轮胎打滑。

**第七步：临时绕行验证**

在 RViz 中观察 `/plan` 是否贴着墙角。如果路径本身离墙太近，先把
`clearance_weight` 调大，再重新规划；不要只调 DWA。

## 12. 安全注意事项

1. 首次实车测试必须把车轮架空。
2. 先低速、短距离目标，确认方向、刹车、急停正常。
3. 动态避障是反应式的，不会预测行人/车辆运动，现场必须有人值守。
4. 玻璃、镜面、强光、悬空物可能导致点云和定位异常。
5. 建图/导航切换前先关闭当前系统，避免重复节点和 TF 冲突。
6. 修改底盘参数或速度限制后，重新做急停测试。
7. 地图自动保存会覆盖 `occupancy_map.*`，需要保留历史时使用结束建图生成的时间戳地图。

## 13. 当前能力边界

- 动态避障基于实时点云 + 局部代价地图 + DWA + 局部 A*，属于反应式避障；
- 没有行人/车辆跟踪与轨迹预测；
- AMCL 使用 3D 点云投影得到的 2D `/scan`，玻璃和长走廊场景可能退化；
- 当前默认使用 FAST-LIO 在线外参估计；LI-Init 离线标定保留为可选流程；
- 当前系统面向单机器人、单层地图。

```text
9. 关闭建图系统
10. ros2 launch bringup navigation.launch.py use_gui:=true use_chassis:=true
11. 设置初始位姿，确认 AMCL 收敛
12. 用地图点选或坐标发送短距离目标
13. 确认底盘方向、速度、急停
14. 逐步增加目标距离和运行时间
```
