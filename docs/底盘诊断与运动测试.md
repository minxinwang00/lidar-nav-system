# 底盘诊断与运动测试

## 当前结论

- `/dev/ttyACM*` 是 MiniPC/STM32 的 USB CDC 接口。
- Linux 串口权限可以通过 udev 规则或 `dialout` 组解决。
- `chassis_bridge` 能打开串口并持续写入 20 字节导航帧。
- 当前 `feedback_protocol: none`，MiniPC 原始串口读取 20 秒没有返回任何字节。
- 因此 `/wheel_odom` 和 `/chassis_status` 不是真实底盘反馈，只是指令回显/积分。

## 必须先满足的控制权条件（2026-11-01 实测）

**遥控器必须开机，并且切到 NAV / 自动 / 电脑控制模式。**

否则会出现：

- `/chassis_status` 显示 `estop=False x=0.20`；
- 串口 TX 帧正确；
- 底盘完全不动；
- 遥控器一切到 NAV 或开机后，同样的帧立刻生效。

这不是 Nav2、不是桥接代码、不是帧编码问题。测试底盘前先检查：

1. 遥控器电池有电并开机；
2. 遥控器模式开关在 NAV/自动档；
3. 底盘没有急停/刹车；
4. MiniPC 已上电。

## 固定串口路径

**不要写死 `/dev/ttyACM0`。** `ttyACM0`/`ttyACM1` 是内核按 USB 枚举顺序分配的
临时编号，重启、重新插拔、先插了别的串口设备，都会让编号变化。它不是设备身份。

稳定身份用：

```text
/dev/serial/by-id/usb-STMicroelectronics_STM32_Virtual_ComPort_206532874D31-if00
```

其中包含厂商、型号、序列号 `206532874D31` 和接口号 `if00`。

发现当前编号：

```bash
ls -l /dev/ttyACM* /dev/ttyUSB* 2>&1
ls -l /dev/serial/by-id/
readlink -f /dev/serial/by-id/usb-STMicroelectronics_STM32_Virtual_ComPort_206532874D31-if00
```

监听插拔事件：

```bash
udevadm monitor --udev --subsystem-match=tty
```

然后插拔底盘 USB，观察 `add/remove` 和 `ttyACM*` 编号变化。

查看稳定路径：

```bash
ls -l /dev/serial/by-id/
```

示例：

```text
/dev/serial/by-id/usb-STMicroelectronics_STM32_Virtual_ComPort_206532874D31-if00
```

可选 udev 规则，创建 `/dev/minipc`：

```bash
sudo tee /etc/udev/rules.d/99-minipc.rules <<'EOF'
KERNEL=="ttyACM*", ATTRS{idVendor}=="0483", ATTRS{idProduct}=="5740", ATTRS{serial}=="206532874D31", ATTRS{bInterfaceNumber}=="00", MODE="0666", GROUP="dialout", SYMLINK+="minipc"
EOF

sudo udevadm control --reload-rules
sudo udevadm trigger
```

重新插拔后：

```bash
ls -l /dev/minipc
readlink -f /dev/minipc
```

也可以直接用仓库里的脚本安装（需要 sudo 一次）：

```bash
sudo bash ~/nav_system_ws/scripts/install_chassis_udev.sh
```

即使忘了装 udev 规则，`chassis_bridge` 也会在 `/dev/minipc` 不存在时按
`/dev/serial/by-id/*STM32_Virtual_ComPort*` 自动查找，不会再因为
`ttyACM0 -> ttyACM1` 变化而静默 fake。

## 1. 原始串口探测

先停止 `chassis_bridge`，否则串口被占用。

只监听，不发送，用遥控器移动底盘：

```bash
ros2 run chassis chassis_serial_probe \
  --port /dev/minipc \
  --seconds 20 \
  --no-write
```

如果 20 秒内一个字节都没有：

```text
MiniPC 没有在这条 CDC 上发送反馈
```

发送前进帧 10 秒：

```bash
ros2 run chassis chassis_serial_probe \
  --port /dev/minipc \
  --seconds 10 \
  --forward 0.1 \
  --field w
```

发送旋转帧 10 秒：

```bash
ros2 run chassis chassis_serial_probe \
  --port /dev/minipc \
  --seconds 10 \
  --angular 0.15 \
  --field w
```

`--field` 可选：

- `w`：写入 `w_speed`
- `yaw`：写入 `yaw_speed`
- `both`：两个字段都写

## 2. 用外部里程计做运动测试

只启动 `chassis_bridge` 和 FAST-LIO，不要启动 `navigation.launch.py`，否则
`bt_main` 也会发布 `/cmd_vel`。

```bash
ros2 run chassis chassis_bridge \
  --ros-args \
  -p port:=/dev/minipc
```

另开终端：

```bash
source /opt/ros/humble/setup.bash
source ~/nav_system_ws/install/setup.bash

ros2 run chassis chassis_motion_test \
  --ros-args \
  -p forward_speed:=0.1 \
  -p forward_duration:=10.0 \
  -p angular_speed:=0.15 \
  -p angular_duration:=10.0
```

它会：

1. 取消导航目标；
2. 解除急停；
3. 前进 10 秒；
4. 停止；
5. 原地旋转 10 秒；
6. 用 `/Odometry` 比较位移和偏航；
7. 最后设置急停。

输出示例：

```text
forward delta_xy=0.98 m  status=...
turn delta_yaw=85.3°     status=...
RESULT forward=PASS turn=PASS
```

注意：

- 必须有人值守，前方空旷；
- 车轮落地；
- `/Odometry` 来自 FAST-LIO，是外部运动参考，不是轮速反馈；
- 如果车轮架空，位移/偏航不会变化。

## 3. 旋转字段自动扫描

“能前进、不能旋转”时，用这个工具一次性测试：

- `w_speed` 正/负
- `yaw_speed` 正/负
- `both` 正/负

它直接打开串口发帧，不经过 `chassis_bridge`，因此必须先停止桥接节点。
同时订阅 FAST-LIO 的 `/Odometry`，用真实偏航变化判断哪个字段有效。

```bash
ros2 run chassis chassis_rotation_sweep --ros-args \
  -p port:=/dev/serial/by-id/usb-STMicroelectronics_STM32_Virtual_ComPort_206532874D31-if00 \
  -p angular_speed:=0.30 \
  -p duration:=5.0 \
  -p settle_time:=2.0
```

默认测试 6 组，每组 5 秒，约 40 秒完成。只想测正向：

```bash
-p sign_mode:=1
```

只测负向：

```bash
-p sign_mode:=-1
```

如果怀疑底盘不能原地旋转（例如阿克曼底盘），加一个前进速度做弧形测试：

```bash
-p linear_speed:=0.10
```

结果示例：

```text
w_speed   sign=+1 delta= +0.42° max_rate=0.001 FAIL
yaw_speed sign=+1 delta=+82.10° max_rate=0.287 PASS
both      sign=+1 delta=+81.60° max_rate=0.285 PASS
最佳字段：yaw_speed sign=+1 delta=+82.10°
建议：chassis_angular_target:=yaw_speed
```

如果全部 FAIL，工具会明确提示：MiniPC 很可能没有执行导航帧，需要检查
NAV/遥控模式、使能、波特率，或固件是否需要额外的模式帧/握手帧。

结果同时写入 `~/.ros/chassis_rotation_sweep_*.csv`。

注意：该工具会检查 `/cmd_vel` 是否还有发布者。如果 `bt_main` 或导航仍在
运行，会拒绝测试；确认安全后可用 `-p force:=true` 跳过检查。

### 本车实测结果（2026-11-01）

遥控器开机 + NAV 模式后：

```text
w_speed   delta=  -0.03° FAIL
yaw_speed delta=-133.10° PASS
both      delta=-132.88° PASS
```

结论：

- 本车旋转字段是 `yaw_speed`；
- 正命令产生负偏航，所以配置：
  - `angular_z_target: yaw_speed`
  - `invert_angular: true`
- `w_speed` 不控制底盘旋转。

## 4. 结果解释

| 结果 | 结论 |
|---|---|
| 前进 PASS，旋转 FAIL | 底盘不支持原地旋转，或旋转字段/单位不对 |
| 前进 FAIL，旋转 FAIL | MiniPC 没有执行导航帧，或串口/模式/使能问题 |
| 前进 PASS，旋转 PASS | 底盘可导航，问题在导航参数/路径 |
| `chassis_status` 有值但测试 FAIL | 串口写入正常，但 MiniPC 没有执行 |
| 旋转扫描只有 `yaw_speed` PASS | 把 `angular_z_target` 改为 `yaw_speed` |
| 旋转扫描只有负方向 PASS | 设置 `invert_angular: true` |

## 4.1 `mode=fake` 的含义

`/chassis_status` 出现：

```text
mode=fake ... serial=FAKE (no serial)
```

说明 `chassis_bridge` 打开串口失败，退化成了假模式：

- `/cmd_vel` 再正常也不会写串口；
- 车一定不动；
- 常见原因：端口被别的进程占用、端口写错、权限不足、设备未插。

检查：

```bash
pgrep -af 'chassis_bridge|chassis_serial_probe|chassis_rotation_sweep'
fuser -v /dev/ttyACM0
ls -l /dev/serial/by-id/
```

实车配置已设置 `fallback_to_fake: false`，串口打不开会直接报错，不再静默假运行。

## 5. 真实反馈的下一步

如果没有原始反馈字节，必须从以下选一条：

1. MiniPC 固件增加周期状态帧；
2. MiniPC 协议增加查询/应答帧；
3. 外接轮速编码器节点；
4. 暂时使用 FAST-LIO `/Odometry` 作为外部运动参考。

在没有真实反馈前，不能仅凭 `/chassis_status` 判断底盘是否使能、是否 NAV、
是否堵转。
