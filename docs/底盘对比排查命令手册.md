# 底盘对比排查命令手册

> **先决条件（实测）：遥控器必须开机并切到 NAV/自动/电脑控制模式。**
> 否则 `/chassis_status` 和 TX 帧都正常，但底盘完全不动。

本文每一步都给出可直接复制执行的命令。默认工作空间：

```bash
cd ~/nav_system_ws
```

## 0. 每个新终端先执行

```bash
cd ~/nav_system_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
```

## 1. 确认串口设备

```bash
ls -l /dev/ttyACM*
ls -l /dev/serial/by-id/
```

取稳定路径：

```bash
readlink -f /dev/serial/by-id/usb-STMicroelectronics_STM32_Virtual_ComPort_206532874D31-if00
```

如果路径不存在，先重新插拔底盘 USB，再执行：

```bash
ls -l /dev/serial/by-id/
```

## 2. 停止旧节点

```bash
pgrep -af 'chassis_bridge|bt_main|navigation.launch|mapping.launch'
```

停止底盘桥：

```bash
pkill -INT -f chassis_bridge
```

停止导航：

```bash
pkill -INT -f bt_main
```

等待 2 秒后确认已经退出：

```bash
sleep 2
pgrep -af 'chassis_bridge|bt_main'
```

没有输出表示已停止。

## 3. 用真实串口启动底盘桥

```bash
ros2 run chassis chassis_bridge --ros-args \
  -p port:=/dev/serial/by-id/usb-STMicroelectronics_STM32_Virtual_ComPort_206532874D31-if00 \
  -p use_serial:=true \
  -p fallback_to_fake:=false
```

另开终端，检查参数：

```bash
ros2 param get /chassis_bridge port
ros2 param get /chassis_bridge use_serial
ros2 param get /chassis_bridge fallback_to_fake
ros2 param get /chassis_bridge angular_z_target
ros2 param get /chassis_bridge feedback_protocol
```

检查状态：

```bash
ros2 topic echo /chassis_status --once
```

必须是：

```text
mode=serial
```

如果是 `mode=fake`，说明串口没打开，先不要继续，执行：

```bash
ls -l /dev/serial/by-id/
fuser -v /dev/ttyACM0
dmesg | tail -30
```

## 4. 手动发前进和旋转指令

前进 3 秒：

```bash
timeout 3 ros2 topic pub -r 10 /cmd_vel \
  geometry_msgs/msg/Twist "{linear: {x: 0.1}, angular: {z: 0.0}}"
```

停止：

```bash
ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist "{}"
```

旋转 3 秒：

```bash
timeout 3 ros2 topic pub -r 10 /cmd_vel \
  geometry_msgs/msg/Twist "{linear: {x: 0.0}, angular: {z: 0.2}}"
```

再次停止：

```bash
ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist "{}"
```

确认 `/cmd_vel` 确实有数据：

```bash
ros2 topic echo /cmd_vel --once
```

## 5. 打印我们实际写出的 20 字节帧

先停止底盘桥：

```bash
pkill -INT -f chassis_bridge
sleep 2
```

带 TX 调试重新启动：

```bash
ros2 run chassis chassis_bridge --ros-args \
  -p port:=/dev/serial/by-id/usb-STMicroelectronics_STM32_Virtual_ComPort_206532874D31-if00 \
  -p debug_frames:=true \
  -p debug_frame_period:=1.0 2>&1 | tee ~/our_tx.log
```

另开终端发前进：

```bash
timeout 3 ros2 topic pub -r 10 /cmd_vel \
  geometry_msgs/msg/Twist "{linear: {x: 0.1}, angular: {z: 0.0}}"
```

停止：

```bash
ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist "{}"
```

发旋转：

```bash
timeout 3 ros2 topic pub -r 10 /cmd_vel \
  geometry_msgs/msg/Twist "{linear: {x: 0.0}, angular: {z: 0.2}}"
```

停止：

```bash
ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist "{}"
```

回到桥接终端按 `Ctrl-C`。

查看最后几条 TX：

```bash
grep -a 'TX ' ~/our_tx.log | tail -10
```

只看非零帧：

```bash
grep -a 'TX ' ~/our_tx.log | grep -a -v '55 04 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 ff' | tail -10
```

正常前进帧示例：

```text
TX 55 04 cd cc cc 3d 00 00 00 00 00 00 00 00 00 00 00 00 00 ff
```

正常 `w_speed` 旋转帧示例：

```text
TX 55 04 00 00 00 00 00 00 00 00 00 00 00 00 cd cc 4c 3e 00 ff
```

## 6. 直接验证串口发帧

先停止底盘桥：

```bash
pkill -INT -f chassis_bridge
sleep 2
```

前进帧：

```bash
ros2 run chassis chassis_serial_probe \
  --port /dev/serial/by-id/usb-STMicroelectronics_STM32_Virtual_ComPort_206532874D31-if00 \
  --seconds 10 \
  --forward 0.1 \
  --echo-tx
```

`w_speed` 旋转帧：

```bash
ros2 run chassis chassis_serial_probe \
  --port /dev/serial/by-id/usb-STMicroelectronics_STM32_Virtual_ComPort_206532874D31-if00 \
  --seconds 10 \
  --angular 0.2 \
  --field w \
  --echo-tx
```

`yaw_speed` 旋转帧：

```bash
ros2 run chassis chassis_serial_probe \
  --port /dev/serial/by-id/usb-STMicroelectronics_STM32_Virtual_ComPort_206532874D31-if00 \
  --seconds 10 \
  --angular 0.2 \
  --field yaw \
  --echo-tx
```

两个字段都写：

```bash
ros2 run chassis chassis_serial_probe \
  --port /dev/serial/by-id/usb-STMicroelectronics_STM32_Virtual_ComPort_206532874D31-if00 \
  --seconds 10 \
  --angular 0.2 \
  --field both \
  --echo-tx
```

弧形测试：前进 0.1 m/s + 旋转 0.2 rad/s。用来判断底盘是否支持原地旋转：

```bash
ros2 run chassis chassis_serial_probe \
  --port /dev/serial/by-id/usb-STMicroelectronics_STM32_Virtual_ComPort_206532874D31-if00 \
  --seconds 10 \
  --forward 0.10 \
  --angular 0.20 \
  --field w \
  --echo-tx
```

把 `--field w` 换成 `--field yaw` 或 `--field both` 再各测一次。

测试 `scan_mod_type=1`（它可能是隐藏的 NAV/模式位）：

```bash
ros2 run chassis chassis_serial_probe \
  --port /dev/serial/by-id/usb-STMicroelectronics_STM32_Virtual_ComPort_206532874D31-if00 \
  --seconds 10 \
  --angular 0.20 \
  --field w \
  --scan-mode \
  --echo-tx
```

前进 + `scan_mod_type=1`：

```bash
ros2 run chassis chassis_serial_probe \
  --port /dev/serial/by-id/usb-STMicroelectronics_STM32_Virtual_ComPort_206532874D31-if00 \
  --seconds 10 \
  --forward 0.10 \
  --scan-mode \
  --echo-tx
```

## 7. 自动扫描旋转字段

先启动 FAST-LIO（终端 A，只启动驱动/FAST-LIO/栅格，不启动导航）：

```bash
cd ~/nav_system_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch bringup mapping.launch.py \
  use_gui:=false \
  use_rviz:=false \
  auto_save:=false
```

另开终端确认有里程计：

```bash

source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 topic hz /Odometry
```

停止底盘桥和导航：

```bash

pkill -INT -f bt_main
sleep 2
```

运行扫描：

```bash
ros2 run chassis chassis_rotation_sweep --ros-args \
  -p port:=/dev/serial/by-id/usb-STMicroelectronics_STM32_Virtual_ComPort_206532874D31-if00 \
  -p angular_speed:=0.30 \
  -p duration:=5.0 \
  -p settle_time:=2.0
```

只测正向：

```bash
ros2 run chassis chassis_rotation_sweep --ros-args \
  -p port:=/dev/serial/by-id/usb-STMicroelectronics_STM32_Virtual_ComPort_206532874D31-if00 \
  -p sign_mode:=1
```

只测负向：

```bash
ros2 run chassis chassis_rotation_sweep --ros-args \
  -p port:=/dev/serial/by-id/usb-STMicroelectronics_STM32_Virtual_ComPort_206532874D31-if00 \
  -p sign_mode:=-1
```

弧形测试（怀疑不能原地旋转时）：

```bash
ros2 run chassis chassis_rotation_sweep --ros-args \
  -p port:=/dev/serial/by-id/usb-STMicroelectronics_STM32_Virtual_ComPort_206532874D31-if00 \
  -p linear_speed:=0.10 \
  -p sign_mode:=1
```

结果会写到：

```bash

```

## 10. 抓同学桥实际发出的串口字节

如果同学能改代码，在他们桥里加同样的 `debug_frames` 日志最稳。

如果不能改，用 `strace`：

```bash
sudo apt install -y strace
```

找进程号：

```bash
pgrep -af chassis
```

假设进程号是 `12345`，抓写串口：

```bash
sudo strace -f -e trace=write -xx -s 200 -p 12345 2>&1 | tee ~/classmate_tx.strace
```

让同学发前进、停止、旋转，然后 `Ctrl-C`。

搜索 0x55 0x04 帧：

```bash
grep -a '\\x55\\x04' ~/classmate_tx.strace | tail -10
```

如果同学用 CAN：

```bash
sudo apt install -y can-utils
ip -details link show can0
candump -L can0 | tee ~/classmate_can.log
```

## 11. 逐字节比较

把我们的旋转帧抄到文件：

```bash
echo "55 04 00 00 00 00 00 00 00 00 00 00 00 00 cd cc 4c 3e 00 ff" > ~/ours_rotate.hex
```

把同学的旋转帧抄到文件：

```bash
echo "55 04 00 00 00 00 00 00 00 00 00 00 00 00 cd cc 4c 3e 00 ff" > ~/theirs_rotate.hex
```

转成二进制并比较：

```bash
xxd -r -p ~/ours_rotate.hex > ~/ours_rotate.bin
xxd -r -p ~/theirs_rotate.hex > ~/theirs_rotate.bin
cmp -l ~/ours_rotate.bin ~/theirs_rotate.bin
```

`cmp -l` 输出的第一列是字节位置，第二列是我们的值，第三列是同学的值。

## 13. 启动完整导航时确认参数

本车实测：`yaw_speed` 有效，且需要 `invert_angular: true`。

```bash
ros2 launch bringup navigation.launch.py \
  use_chassis:=true \
  chassis_port:=/dev/serial/by-id/usb-STMicroelectronics_STM32_Virtual_ComPort_206532874D31-if00 \
  chassis_angular_target:=yaw_speed \
  use_gui:=true
```

运行中检查：

```bash
ros2 param get /chassis_bridge port
ros2 param get /chassis_bridge angular_z_target
ros2 topic echo /chassis_status --once
```

## 14. 判断结论

| 现象 | 结论 |
|---|---|
| `mode=fake` | 串口没打开，先修设备/权限/端口 |
| `mode=serial`，TX 有非零帧，但车不动 | MiniPC 没执行帧，查模式/使能/波特率 |
| 前进 TX 正常，旋转 TX 也有非零帧，但车不转 | 字段语义或底盘类型问题 |
| 同学 TX 帧和我们不同 | 直接按同学帧修改编码 |
| 同学 TX 帧和我们相同，但同学能转 | 模式/使能/固件/硬件差异 |
| 扫描只有 `yaw_speed` PASS | 改 `angular_z_target:=yaw_speed` |
| 扫描只有负方向 PASS | 设置 `invert_angular:=true` |
| 全部 FAIL | 不要再调 Nav2，先解决底盘授权和协议 |
