# 光滑地面防滑与里程计漂移

## 现象

- 地面很滑，轮子空转，车几乎原地不动；
- 但 RViz/GUI 里机器人位置却走了很远；
- 导航继续给速度，车子打滑更严重。

这类问题要区分三层：

1. **FAST-LIO 里程计漂移**：`odom -> base_link` 自己在走；
2. **AMCL 修正跳变**：`map -> odom` 在跳；
3. **底盘指令积分**：`/wheel_odom` 只是命令积分，不是真实反馈。

## 先判断是哪一层

导航运行、车轮打滑时，在另一个终端执行：

```bash
cd ~/nav_system_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 run tf2_ros tf2_echo odom base_link
```

- 如果这里的位置/yaw 持续增长，而车没动：**FAST-LIO 漂移**；
- 如果这里稳定，但地图上的车在跑：看 `map -> odom`：

```bash
ros2 run tf2_ros tf2_echo map odom
```

- 如果 `map -> odom` 在跳：AMCL 问题；
- 如果两者都稳定，只是 `/wheel_odom` 在跑：那是底盘桥的指令积分，
  导航不应该使用它。

## 已做的软件调整

### 1. 关闭 FAST-LIO 在线外参估计

MID-360 的 LiDAR/IMU 在同一壳体内，厂家外参接近单位阵。  
光滑地面打滑时，在线估计 `extrinsic_est_en` 容易被 IMU 噪声带偏。

`src/mapping/FAST_LIO/config/mid360.yaml`：

```yaml
extrinsic_est_en: false
extrinsic_T: [0.0, 0.0, 0.0]
extrinsic_R: [1., 0., 0.,
              0., 1., 0.,
              0., 0., 1.]
```

### 2. 提高配准稳定性

```yaml
point_filter_num: 2
max_iteration: 5
filter_size_surf: 0.2
filter_size_map: 0.2
```

保留更多结构点，弱特征/光滑环境下配准更稳。

### 3. 速度与加速度上限

当前为了提速，`nav_params.yaml` 使用：

```yaml
max_linear: 0.50
max_angular: 1.10
max_dv: 0.18
max_dw: 0.70
```

光滑地面如果在提速后出现轮子空转或里程计漂移，优先回调
`max_linear` 和 `max_dv`，不要只加导航增益。

### 4. 底盘速度比例

实测底盘实际速度约为命令值的 0.4~0.6 倍。  
如果仍然打滑，可以进一步降低：

```yaml
max_linear: 0.20
max_angular: 0.60
max_dv: 0.05
max_dw: 0.30
```

## 物理措施（比软件更有效）

- 换橡胶/软胎，增大摩擦；
- 清理地面灰尘、水、油；
- 增加驱动轮正压力（配重）；
- 避免急加速、急转、原地旋转；
- 起步用低速，确认不打滑再加速。

## 如果仍然漂移

如果 `odom -> base_link` 在车不动时仍持续增长，说明 FAST-LIO 在这种
光滑/弱特征场地下退化。可选方案：

1. 使用真实轮速/编码器反馈，做轮速 + IMU 融合；
2. 增加外部定位（AMCL/视觉/动捕）；
3. 在场地增加可识别特征（箱子、标记物）；
4. 降低速度，减少轮子空转。

注意：轮子空转时，轮速编码器也会报告“在走”，所以单纯轮速里程计
不能解决打滑，只能用于和 LiDAR 相互校验。
